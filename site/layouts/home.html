飾り

Self-hosted publishing for the pages AI agents build

Ask your agent for a page. Share it on your domain.

Kazari is a small, self-hosted home for what AI agents build: prototypes, reports, dashboards and demos. It works with any agent, in the cloud or self-hosted. Every page gets its own address, every change is kept as a version, and people can sign in with the work account they already have.

From a sentence to a link

  1. 1

    Connect

    Add Kazari's MCP address to your agent, in the cloud or on your own machine, and sign in with your work account or an API key.

    Describe what you want. Your agent writes the page, publishes it with Kazari's tools and replies with the link.

    Ask for changes and your agent publishes a new version. The link stays the same, and every version keeps an address of its own.

アドレス

Every page is its own site

Kazari serves each artifact from its own subdomain under one wildcard certificate. Each is a separate browser origin, so one page can't read another's cookies or storage.

Versions never change. Put a version link in a review thread and it will always show what the reviewer saw.

onboarding.art.example.com

The published version. It moves when you publish or roll back.

onboarding--v3.art.example.com

Version 3, for good. Safe to cache, safe to link.

mcp.art.example.com

The MCP server for agents, beside api. for the REST API and admin. for operators.

v1v2v3v4published

Rolling back moves a pointer. Nothing is copied and nothing is lost.

機能

What a team needs, and little else

{{ partial "icon.html" "layers" }}

Versions you can trust

Every publish is an immutable, content-addressed version. Roll back or forward with one call; optimistic concurrency stops lost updates.

{{ partial "icon.html" "plug" }}

Three ways in

An MCP server with nineteen tools, a REST API and a CLI, all on one service layer and all returning the same JSON. Agents edit pages in place and load the instance's own skill.

{{ partial "icon.html" "key" }}

Your sign-in

OAuth 2.1 for MCP clients, federated to Microsoft Entra ID, Google Workspace, Okta, Keycloak or any OpenID Connect provider. No passwords stored.

{{ partial "icon.html" "shield" }}

Safe defaults

An origin per page, a Content-Security-Policy that still allows the common CDNs, no search indexing unless you ask, quotas and rate limits.

{{ partial "icon.html" "upload" }}

Small pages and big sites

Inline files for a single page, tar.gz bundles for whole sites, resumable chunked uploads for MCP clients without a shell.

{{ partial "icon.html" "box" }}

Simple to run

One static Go binary or a distroless image. SQLite and a directory of blobs are the only state. Wildcard certificates by ACME DNS-01.

{{ partial "icon.html" "activity" }}

Observable

OpenTelemetry traces of every request and tool call, Prometheus metrics, structured logs, an admin API and an append-only audit log of every change.

{{ partial "icon.html" "clock" }}

Tidy by default

Pages you no longer need retire themselves on a schedule you set, and every step up to the purge can be undone.

片付け

Pages that tidy up after themselves

Generated pages pile up. Mark one stale and it keeps serving through a grace period, then steps out of the way. Each step lands in the audit log, and everything short of the purge can be reversed.

How the lifecycle works {{ partial "icon.html" "arrow" }}
  1. PublishedServing at its address
  2. StaleStill serving for the grace period, 14 days by default
  3. Soft-deletedOffline, restorable for 30 days
  4. PurgedGone; old links answer 410 for 90 days
  5. Slug freeThe name can be used again

Running in minutes

Try it on your machine

No domain or certificate needed: browsers resolve *.localhost to your own computer.

{{ partial "snippet.html" (dict "lang" "sh" "code" ` docker run -d --name kazari -p 127.0.0.1:8080:8080 -e KAZARI_LISTEN_HTTP=:8080 \ ghcr.io/peterbooker/kazari:latest serve --local docker exec kazari kazari admin users create ana --role admin docker exec kazari kazari admin keys issue ana --label laptop # pages appear at http://.localhost:8080/` ) }} Quick start {{ partial "icon.html" "arrow" }}

Run it for your team

You need a domain, a wildcard DNS record and a DNS API token for the certificate, or a reverse proxy that already has one. Two short files configure it, under Compose, a package or the binary alike.

{{ partial "snippet.html" (dict "lang" "sh" "code" ` curl -fsSLO https://kazari.io/deploy/compose.yml curl -fsSLO https://kazari.io/deploy/kazari.yaml # your domain, email, DNS provider curl -fsSL https://kazari.io/deploy/kazari.env.example -o .env # the DNS token docker compose up -d docker compose exec kazari kazari admin users create ana --role admin` ) }} Installation guide {{ partial "icon.html" "arrow" }}
