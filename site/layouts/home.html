How it works

From a sentence to a link

  1. 1

    Connect

    Add Agalma to claude.ai as a custom connector, or to Claude Code with one command, and sign in with your work account or an API key.

  2. 2

    Ask

    Describe what you want. Claude writes the page, publishes it with Agalma's tools and replies with the link.

  3. 3

    Iterate and share

    Ask for changes and Claude publishes a new version. The link stays the same, and every version keeps an address of its own.

Addresses

Every page is its own site

Agalma serves each artifact from its own subdomain under one wildcard certificate. Each is a separate browser origin, so one page can't read another's cookies or storage.

Versions never change. Put a version link in a review thread and it will always show what the reviewer saw.

Features

What a team needs, and little else

{{ partial "icon.html" "layers" }}

Versions you can trust

Every publish is an immutable, content-addressed version. Roll back or forward with one call; optimistic concurrency stops lost updates.

{{ partial "icon.html" "plug" }}

Three ways in

An MCP server with twelve tools, a REST API and a CLI, all on one service layer and all returning the same JSON.

{{ partial "icon.html" "key" }}

Your sign-in

OAuth 2.1 for MCP clients, federated to Microsoft Entra ID, Google Workspace, Okta, Keycloak or any OpenID Connect provider. No passwords stored.

{{ partial "icon.html" "shield" }}

Safe defaults

An origin per page, a Content-Security-Policy that still allows the common CDNs, no search indexing unless you ask, quotas and rate limits.

{{ partial "icon.html" "upload" }}

Small pages and big sites

Inline files for a single page, tar.gz bundles for whole sites, resumable chunked uploads for MCP clients without a shell.

{{ partial "icon.html" "box" }}

Simple to run

One static Go binary or a distroless image. SQLite and a directory of blobs are the only state. Wildcard certificates by ACME DNS-01.

{{ partial "icon.html" "activity" }}

Observable

Structured request logs, Prometheus metrics, an admin API and an append-only audit log of every change.

{{ partial "icon.html" "clock" }}

Tidy by default

Pages you no longer need retire themselves on a schedule you set, and every step up to the purge can be undone.

Lifecycle

Pages that tidy up after themselves

Generated pages pile up. Mark one stale and it keeps serving through a grace period, then steps out of the way. Each step lands in the audit log, and everything short of the purge can be reversed.

How the lifecycle works {{ partial "icon.html" "arrow" }}
  1. PublishedServing at its address
  2. StaleStill serving for the grace period, 14 days by default
  3. Soft-deletedOffline, restorable for 30 days
  4. PurgedGone; old links answer 410 for 90 days
  5. Slug freeThe name can be used again

Self-hosting

Running in minutes

Try it on your machine

No domain or certificate needed: browsers resolve *.localhost to your own computer.

{{ partial "snippet.html" (dict "lang" "sh" "code" ` git clone https://github.com/PeterBooker/agalma.git cd agalma docker compose up --build -d # pages appear at http://.localhost:8080/` ) }} Quick start {{ partial "icon.html" "arrow" }}

Run it for your team

You need a domain, a wildcard DNS record and a DNS API token for the certificate, or a reverse proxy that already has one.

{{ partial "snippet.html" (dict "lang" "sh" "code" ` docker run -d --name agalma -p 80:80 -p 443:443 \ -v /srv/agalma/data:/var/lib/agalma \ -e AGALMA_BASE_DOMAIN=art.example.com \ -e AGALMA_TLS_EMAIL=ops@example.com \ -e AGALMA_TLS_DNS_PROVIDER=cloudflare \ -e AGALMA_TLS_DNS_API_TOKEN=cf-token \ -e AGALMA_AUTH_ADMIN_TOKEN="$(openssl rand -hex 32)" \ ghcr.io/peterbooker/agalma:latest serve` ) }} Installation guide {{ partial "icon.html" "arrow" }}
