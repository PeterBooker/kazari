# Kazari

Kazari hosts static web pages. Each artifact has a permanent slug and is served at https://<slug>.<base>/ (the published version) and at https://<slug>--v<N>.<base>/ (version N, forever). This file is generated by the instance, so the limits and the policy below are its real settings; the tool descriptions say the same.

## Connect

Add `https://mcp.<base>/` as a remote MCP server (Streamable HTTP). Claude Code: `claude mcp add --transport http kazari https://mcp.<base>/`, then sign in when asked, or add `--header "Authorization: Bearer <API key>"`.

## Workflow

1. **Publish a page:** `create_artifact` with `slug`, `name`, `description` and `files`. Report the `url` from the result to the user.
2. **Copy an existing page:** `import_page` with the page's `url` and a `slug` fetches it with its stylesheets, fonts and images, removes its scripts and publishes the copy; use it, never your own fetch of the page, whenever the user wants a page copied or used as a starting point. The result's `import` field lists what stayed remote (`skipped`), notes such as a page that renders with JavaScript, and an `outline` of the page's sections with the line and opening tag of each. Change the copy with `edit_file`: a text edit whose `old_text` is an outline tag, and whose `new_text` is the new content followed by that tag, inserts before the section; on a page kept on few lines, read a window around the line first.
3. **Change a page:** `read_file` with `anchors: true`, then `edit_file` with `expected_version` set to the `latest_version` the read returned. `update_artifact` adds or replaces whole files and removes them with `{path, delete: true}`, with `expected_version` too; every file not mentioned carries over. To make a version hold exactly a set of files, list the latest version's paths with `get_artifact` and `include_files` and send a delete entry for each path not in the set. A change that spans several files is atomic only as one `update_artifact` call with the whole files; `edit_file` publishes each file as its own version.
4. **On `version_conflict` or `anchor_mismatch`:** read the file again and redo the edit against the new text. Never resend a failed edit unchanged.
5. **Large content** (any file, or all files together, above 2 MiB): `begin_upload`, stage the files, then `create_artifact` or `update_artifact` with `upload_id`. Without a shell, stage with `upload_chunk` for each file, `offset: 0` first and the `bytes_received` of the previous chunk after that. With a shell, archive the files from inside the page's directory (`zip -r ../site.zip .` or `tar czf ../site.tar.gz .`, so paths start at the page root), call `begin_upload` with `archive_sha256` (`sha256sum site.zip`) and `archive_bytes` (`wc -c < site.zip`), and send it with `curl --fail-with-body -T site.zip '<archive_url>'`: the URL needs no credential, accepts only that digest and is spent by the first body that matches; the archive may be at most 50 MiB. Inline `files` in the publishing call are merged with the staged ones and win on a path clash, and the call consumes the upload whether it succeeds or fails. `discard_upload` drops an upload you no longer need.
6. **Inspect:** `get_artifact` (`include_files` lists every version's paths and hashes), `read_file` (text inline, `anchors: true` for edits, `start_line` and `end_line` for a window of a large text file, small binaries as base64, larger files as a download URL) and `list_artifacts` (`mine`, `metadata`, `stale`, `deleted`, `cursor`).
7. **Roll back:** `get_artifact` lists the versions; `publish_version` serves one again.
8. **Share privately:** `visibility: "members"` serves a page only to people who sign in to this instance. For someone who cannot, `create_share_link` returns a URL that opens it until it expires; give the user that `url`, and `revoke_share_link` ends it. Slugs are easy to guess, so a page is never private by its URL alone.
9. **Retire:** prefer `set_visibility` `"unpublished"` (reversible) or `mark_stale` (expires after a grace period) to `delete_artifact`. Ask the user before `delete_artifact` with `hard: true`; clients that support it also show the user a confirmation. Without `hard`, `delete_artifact` soft-deletes, and `update_artifact` with `restore: true` brings the artifact back until it is purged.

## Editing a file

`edit_file` changes one text file of the latest version and publishes the result as a new version; every other file carries over. Only the changed text is sent.

- **Text edits** (the default): each edit has `old_text`, copied exactly from the file, and `new_text`. `old_text` must match once: add surrounding lines to make it unique, or set `replace_all`. Edits apply in order, each to the result of the one before.
- If `old_text` does not match exactly, whole lines are compared ignoring trailing whitespace, then ignoring indentation, and `new_text` is re-indented to fit. Each edit's `match` in the result says which was used: `exact`, `trailing_whitespace` or `indentation`. A miss names the closest lines with their anchors.
- **Anchor edits:** `read_file` with `anchors: true` prefixes every line with `<line>:<hash>|`, e.g. `12:3fa0|<h1>Title</h1>`. An edit with `start` (and optionally `end`) replaces those lines, inclusive, with `new_text`; an empty `new_text` deletes them. To insert, replace a line with itself plus the new lines. Every anchor in one call refers to the file as read, and the ranges must not overlap. A line that changed since the read fails with `anchor_mismatch`, so nothing is overwritten by mistake.
- One call takes text edits or anchor edits, at most 100.
- The result has the new `version` and, for each edit, `start_line`, `end_line` and an anchored `excerpt` of the new text, so a follow-up anchor edit needs no new read. Lines longer than 160 bytes are clipped in excerpts ("…[+N bytes]"): read the file before rewriting such a line whole.
- `edit_file` edits the latest version. `read_file` reads the published version unless given `version`; when its `latest_version` differs from its `version` (after a rollback), read `version: latest_version` before editing.
- A text file above the inline read limit (1 MiB) comes back as a download URL. Read it in windows with `start_line` and `end_line` instead: the lines carry the same anchors, the result states `total_lines`, and the note says where to continue when the window was cut short.

## Authoring conventions

- Build a self-contained `index.html`; it is served at https://<slug>.<base>/. Extra files (CSS, JavaScript, images) are fine.
- Use relative links (`about.html`, `assets/app.js`), never paths starting with `/`, so the page also works on pinned version URLs.
- Content-Security-Policy (CSP) on every page allows scripts from own files, inline, https://cdnjs.cloudflare.com, https://cdn.jsdelivr.net, https://unpkg.com; styles from own files, inline, https://fonts.googleapis.com; fonts from own files, https://fonts.gstatic.com; images from own files, data: URIs, any https: URL; fetch/XHR/WebSocket from own files. Pages cannot be embedded in frames. Anything else is blocked by the browser: inline your code or ship libraries as files. Policy: default-src 'self'; script-src 'self' 'unsafe-inline' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net https://unpkg.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data: https:; connect-src 'self'; frame-ancestors 'none'
- No server-side code: no PHP, API routes, databases or server build step. Ship the built output.
- Forms and payments: nothing runs on the server, so a form cannot be handled here. For donations or payments, link to or post to a provider-hosted checkout that needs no script, such as a Stripe Payment Link (`<a href="https://buy.stripe.com/...">`) or a PayPal Donate form (`<form action="https://www.paypal.com/donate" method="post">`): a navigation is allowed by the policy above. A provider's own script or embedded iframe needs its origins in the policy, through `kazari.csp` metadata where the instance allows overrides.
- Slug rules: 3 to 63 characters of lower-case letters a-z, digits 0-9 and hyphens; starts and ends with a letter or digit; no "--" (reserved for version hosts); not one of the reserved slugs (api, mcp, admin, www, mail, ns1, ns2, autoconfig, autodiscover, localhost). The slug is permanent and becomes the host name: https://<slug>.<base>/. On `slug_taken`, pick another.
- Limits: each file at most 25 MiB, each version at most 50 MiB in total, at most 2000 files per version.
- Text fields: name at most 256 bytes and label at most 256 bytes, each on one line; description at most 4096 bytes (line breaks allowed); none may contain other control characters.
- A file can give url instead of content: an http or https address on a public host, without credentials, that the server downloads as the file's content, up to the file limit and, all of a call's url files together, within the version limit and the fetch budget (content_type is taken from the response when omitted). A download that fails fails the whole call with fetch_failed, and nothing is published.
- Metadata is a string map. Keys the server interprets: kazari.spa="true" serves index.html for any missing path without a file extension (client-side routing); kazari.indexable="true" lets search engines index the page (the default sends X-Robots-Tag: noindex); kazari.csp replaces the Content-Security-Policy for this artifact when the instance allows overrides. Any other key (letters, digits, "_", ".", "-", at most 64 characters) is a free-form label that list_artifacts can filter on.

## Errors

A failed call returns `<code>: <message>`, and usually a `Next step:` line. Follow it.

| Code | Next step |
| ---- | --------- |
| `version_conflict` | Someone published since you read it: read the artifact again (get_artifact, or read_file for the file), redo your change on the new content and retry with expected_version set to the new latest_version. |
| `anchor_mismatch` | The file changed since you read it: call read_file with anchors: true for fresh anchors, then redo the edit. |
| `edit_not_found` | Copy old_text exactly from the current file (read_file shows it; the error names the closest lines), or switch to anchor edits. |
| `edit_ambiguous` | Add surrounding lines to old_text until it matches once, or set replace_all to change every match. |
| `slug_taken` | Pick another slug and call create_artifact again. To change the existing artifact, use edit_file or update_artifact on it instead. |
| `invalid_slug` | Choose a slug that follows the slug rules in the create_artifact description. |
| `invalid_path` | Use a relative path without "..", a leading "/" or a trailing "/", such as assets/app.js. |
| `invalid_metadata` | Fix the key or value the message names; the metadata rules are in the create_artifact description. |
| `invalid_argument` | Fix the argument the message names, then call again. |
| `not_found` | Check the slug: list_artifacts with mine "any" lists the artifacts you created or updated, and deleted "include" adds soft-deleted ones. If get_artifact shows deleted_at, the artifact is soft-deleted: update_artifact with restore: true brings it back. |
| `file_not_found` | Call get_artifact with include_files: it lists the paths in each version. |
| `version_not_found` | Call get_artifact: it lists the versions that exist. |
| `gone` | The artifact was purged and cannot be restored. Publish the content again under a new slug; the old one stays blocked for a while. |
| `too_large` | The limits are in the create_artifact description and cannot be raised by the call. Content above 2 MiB that is within them goes through begin_upload and upload_chunk. |
| `too_many_files` | Bundle fewer files, for example by inlining small CSS and JavaScript into the HTML. |
| `quota_exceeded` | The owner's storage quota is full. Tell the user: deleting old artifacts or a larger quota from an admin frees space. |
| `upload_not_found` | The upload expired or was used by an earlier create_artifact or update_artifact call. Start again with begin_upload. |
| `upload_offset_mismatch` | Resend that path from the offset given as current. |
| `too_many_uploads` | Discard the open uploads you no longer need with discard_upload (their ids came from begin_upload), then begin a new one; unused uploads also expire on their own. |
| `share_link_not_found` | Call list_share_links: it lists the prefixes of the artifact's share links. |
| `fetch_failed` | The server could not fetch that URL; the message says what happened. Check the address is public and serves the file. A page behind a login, a CAPTCHA or bot protection cannot be fetched: ask the user to save it from their browser and publish the files with create_artifact or kazari publish. |
| `forbidden` | Retrying will not help. Tell the user: the connection's credential lacks the scope, or the instance's write policy reserves the artifact for its owner. |
| `rate_limited` | Wait as long as the message says, then repeat the call. |
| `internal` | The server failed. Retry once; if it fails again, tell the user. |
